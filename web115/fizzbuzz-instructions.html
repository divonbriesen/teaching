Fizz Buzz Instructions

Five labs, each one built on the last. Look up "FizzBuzz" online first. It's a kids' math game and a programming interview question, and you'll build a bigger version each time until you're taking and checking user input and testing for several numbers at once.

Each lab starts as a copy of the one before it. Keep everything that was there and add the new part.

Every Fizz Buzz Page

  • Save it as fizzbuzz0.html, fizzbuzz1.html and so on (lowercase, no spaces). Link each one from your course TOC.
  • It's a branded page with all the normal requirements. The h2 is the page name and nothing else: "Fizz Buzz 0", or "FizzBuzz 0" if you leave out the space (then the B is a capital).
  • Each page links its own script file. Make a new script when you copy the page, and link the new one.
  • Under the h2, add a greeting. It's an h3 with the id greeting. It says welcome (with or without a name or brand) and ends in !, like "Welcome to DI's Donuts!"
  • Add a form with text fields for first name, middle name or initial, and last name. Give them ids like first_name, middle_initial and last_name. Hyphens (first-name) or camelCase (firstName) are fine too. Pick one style and use it for every id on the page. Use placeholders (the grey hint text inside the field) or labels so people know what goes where.
  • When the form is submitted, use DOM manipulation to replace the greeting with one that has the full name: first name, the first letter of the middle name followed by a period, then last name. Someone who types "Jay" or "J" in the middle field gets "J." either way. "Welcome to DI's Donuts! John J. Jingleheimer!"
  • Get the field values with getElementById, build the message, and put it back into the greeting heading.

Fizz Buzz 0

Part 1

  • Add a loop that runs when the new greeting appears and outputs 125 identical lines of two words related to your theme, each with a number in front. Two words only.
  • Format the lines however you like. Watch your line breaks, or use an ordered or unordered list.

Part 2

  • Ask the user how high to count, using their first name (prompt("How high do you want to count, John?")), and loop that many times instead of 125.
  • Add an if/else inside the loop. If the counter is even (iCounter % 2 === 0), the line says the number is even. If not, it says the number is odd. Same line as your two words:
    1) Bazoom Bazang - the number is odd

Fizz Buzz 1

Copy Fizz Buzz 0, rename it, add it to your TOC, and give it a new script. Keep the greeting. The form and the loop change.

  • Take out the pop-up prompt and the even/odd message from Fizz Buzz 0. The form does that job now.
  • Put the name fields on one line: first, middle, last, in that order, with no div, p or br between them (labels are fine). Add a second line with a start number and an end number. Prefill them with 1 and 140.
  • When the form is submitted, output a numbered list from the start number to the end number, number at the start of each line. Add a word from your theme, or just the number.
  • When the counter is evenly divisible by 3, say a second word of your choice.
  • Do the same for 5 with a third word.
  • When a number is divisible by both, say both words.

You'll keep changing this, so write it so it's easy to change.

Fizz Buzz 2

Copy Fizz Buzz 1 the same way (new name, TOC link, new script).

  • Don't type 3 and 5 into your tests. Put them in variables near the top, like firstDivisor and secondDivisor. Use 3 and 5 or pick your own.
  • Write a function that takes two numbers and returns true if the first divides evenly by the second and false if not. It's a one-line function. Make it longer if that reads better.
  • Use it in your loop. Instead of if (iCounter % secondDivisor === 0), write if (checkDivision(iCounter, secondDivisor)) (or whatever you named your function).

It doesn't make the program much shorter. It makes it easier to change, which Fizz Buzz 3 and 4 need.

Fizz Buzz 3 - Fizz, Buzz, BANG!

Everything from Fizz Buzz 2, plus a third number.

  • Add 7, which says BANG! (or your word).
  • Cover every combination of 3, 5 and 7. A number divisible by 3 and 7 says both words, and so on.
  • Don't brute-force it by writing a separate branch for each combination. Write it so that adding a fourth number would not mean writing more branches.

Fizz Buzz 4 - Fizz, Buzz, EVERYTHING

Fizz Buzz 3, except now the user picks the numbers. You already have the name fields and the start and end numbers. Set the end number to 125, and add these fields to the form:

  • the 3 numbers to divide by
  • the 3 words to output
  • a field for numbers that nothing divides into. Leave it BLANK (nothing in it), so those lines show only the number.

Prefill the other fields with your own numbers and words (one word per field). When the form is submitted, use JavaScript to read the values and print the list for that range back on the page, like your earlier Fizz Buzz pages. Make it readable and easy to use, and add instructions or explanations wherever people might wonder what a field is for.

What the Validator Checks

The validator checks the page, not your JavaScript. On each Fizz Buzz page it looks for:

  • an h2 that says Fizz Buzz and the lab number, and nothing else
  • your own script file linked
  • the h3 greeting (welcome, ending in !) with the id greeting
  • first, middle and last name fields with ids like first_name
  • placeholders or labels on the fields
  • on Fizz Buzz 1 to 3, at least 5 fields (3 names, start and end)
  • on Fizz Buzz 4, at least 12 fields and an end number of 125

Your reviewers check the rest with the review checklist: the 140 lines, the divisor variables, the function, the 7 and BANG, no brute force, the blank field, and one word per field.
